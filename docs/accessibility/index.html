Accessibility statement

Last updated: October 29, 2026

I want this website to be usable by everyone, including people who use screen readers, keyboard navigation, magnification or other assistive technology.

Standard

The site is built to meet the Web Content Accessibility Guidelines (WCAG) 2.1 at level AA. This covers the requirements of Israeli Standard 5568, which is based on WCAG 2.0 level AA, under the Equal Rights for Persons with Disabilities (Service Accessibility Adjustments) Regulations, 5773-2013.

What was done

  • Semantic structure: one main heading per page, landmarks, labelled navigation and breadcrumbs.
  • Full keyboard use, a "skip to content" link, and a clearly visible focus outline.
  • Text and controls meet WCAG AA contrast in both the dark and light themes, which follow your system setting.
  • Every image has a text alternative that describes what it shows.
  • Text resizes up to 200% without loss of content, and layouts adapt to small screens.
  • No content flashes or moves on its own, and the site honours the "reduce motion" setting.
  • Questions and answers use native disclosure elements that work with screen readers.
  • Pages were checked with the automated axe accessibility tester and by keyboard.

Known limitations

  • The product screenshots are images of software. Each has a text description, and the same information appears in the page text.
  • Links to GitHub and Agensi lead to sites with their own accessibility.

Report a problem

If something on the site is hard to use, please open a GitHub issue describing the page and the problem. Accessibility issues are handled first, with a reply within 2 business days. Contact: Bar Madar.
